# Plan 02-03: Bulk Catalog Import with SheetJS, Pre-commit Validation Preview, and Sample CSV

<objective>
Enable frictionless, error-free onboarding and catalog replenishment by implementing spreadsheet import (.csv and .xlsx) via SheetJS, with automatic header normalization, Zod-backed row validation, a pre-commit validation preview modal displaying valid vs. rejected rows with error explanations, downloadable sample CSV template, and atomic batch persistence with movement logging per D-10, D-11, and D-12.
</objective>

<threat_model>
ASVS Level 1:
- Malformed spreadsheet injection: Mitigated by in-browser Zod schema validation before writing to Firestore.
- Batch write exhaustion: Mitigated by chunking Firestore batch writes into compliant batch sizes (< 500 operations).
- Inconsistent audit log on bulk imports: Mitigated by committing initial 'creation' movements in tandem with newly imported items.
</threat_model>

<tasks>
<task type="tracer">
  <name>Build spreadsheet parsing and validation engine with downloadable CSV template generator</name>
  <files>src/lib/import-utils.ts</files>
  <read_first>src/types/inventory.ts</read_first>
  <action>
    Create `src/lib/import-utils.ts` providing:
    1. `parseSpreadsheetFile(file: File)`:
       - Reads file buffer using `FileReader` as `ArrayBuffer`.
       - Parses workbook with `xlsx.read`.
       - Normalizes column names (case-insensitive and alias matching: `name` / `item name`, `category`, `price` / `unit price`, `quantity` / `stock` / `qty`, `threshold` / `low stock threshold`, `description`).
    2. Zod row validator:
       - `name`: string (1-100 chars, trimmed).
       - `category`: string (1-50 chars, trimmed, default "General").
       - `price`: non-negative number.
       - `quantity`: non-negative integer.
       - `lowStockThreshold`: optional non-negative integer (default 10).
       - `description`: optional string (max 500 chars).
    3. Return structured analysis: `{ validItems: Omit<InventoryItem, 'id'>[], invalidRows: { rowNumber: number; raw: any; errors: string[] }[], totalRows: number }`.
    4. `downloadSampleCsvTemplate()`:
       - Generates and downloads `stockpilot_inventory_template.csv` using SheetJS with standard headers and 3 clean sample rows.
  </action>
  <acceptance_criteria>
    - `parseSpreadsheetFile` correctly extracts rows from CSV and XLSX.
    - Valid items conform to `InventoryItem` type.
    - Invalid rows identify specific validation failures (e.g., negative price, missing name).
    - `downloadSampleCsvTemplate` triggers browser download of valid CSV template.
  </acceptance_criteria>
  <verify>
    <automated>npm run typecheck</automated>
    <fails_when>TypeScript typecheck error</fails_when>
  </verify>
  <done>
    Parsing, validation, and sample template utilities provide a robust foundation for spreadsheet ingestion.
  </done>

<task type="auto">
  <name>Implement bulkAddItems with writeBatch in use-inventory hook</name>
  <files>src/hooks/use-inventory.ts</files>
  <read_first>src/hooks/use-inventory.ts, src/types/inventory.ts</read_first>
  <action>
    In `src/hooks/use-inventory.ts`, implement `bulkAddItems(items: Omit<InventoryItem, 'id'>[])`:
    1. Verify user is authenticated.
    2. Chunk items into batches of 200 (to stay safely within Firestore's 500 operation limit per `writeBatch`, since each item generates 1 item document + 1 movement document = 2 operations).
    3. For each item:
       - Generate new doc reference in `/users/{user.uid}/items`.
       - Set item data in batch.
       - Generate new doc reference in `/users/{user.uid}/movements`.
       - Set movement audit record (`type: 'creation'`, `delta: item.quantity`, `previousQuantity: 0`, `newQuantity: item.quantity`, `note: 'Bulk imported via spreadsheet'`) in batch.
    4. Commit batch writes sequentially and handle error states gracefully.
  </action>
  <acceptance_criteria>
    - `bulkAddItems` commits all valid items into Firestore atomically.
    - Matching 'creation' movements are created for each imported item.
    - Large imports (> 200 items) are properly chunked without exceeding Firestore write limits.
  </acceptance_criteria>
  <verify>
    <automated>npm run typecheck</automated>
    <fails_when>TypeScript typecheck error</fails_when>
  </verify>
  <done>
    `use-inventory` supports high-performance atomic bulk creation with full audit logging compliance.
  </done>
</task>
