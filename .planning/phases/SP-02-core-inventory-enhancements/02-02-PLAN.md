# Plan 02-02: Immutable Movement Audit Trail Subcollection and History Timeline

<objective>
Establish an auditable inventory change record by provisioning a dedicated `/users/{userId}/movements/{movementId}` subcollection protected by immutable security rules (allow create and read; deny update and delete), automatically capturing stock movements on item creation, adjustment, and deletion in `use-inventory.ts`, and presenting an interactive chronological Movement History modal in the UI per D-04, D-05, D-06, and D-07.
</objective>

<threat_model>
ASVS Level 1:
- Audit record tampering/erasure: Mitigated by Firestore rule `allow update, delete: if false` on movements subcollection (D-05).
- Cross-tenant audit leakage: Mitigated by scoping movements under `/users/{userId}/movements` and verifying `isOwner(userId)`.
- Untracked inventory mutations: Automated in hook level so all mutations dispatch a movement document.
</threat_model>

<task type="tracer">
  <name>Define StockMovement data model and immutable Firestore security rules</name>
  <files>src/types/inventory.ts, firestore.rules</files>
  <read_first>src/types/inventory.ts, firestore.rules</read_first>
  <action>
    1. In `src/types/inventory.ts`, export the `StockMovement` interface:
       ```ts
       export interface StockMovement {
         id: string;
         itemId: string;
         itemName: string;
         type: 'creation' | 'restock' | 'reduction' | 'adjustment' | 'deletion';
         delta: number;
         previousQuantity: number;
         newQuantity: number;
         timestamp: number;
         note?: string;
       }
       ```
    2. In `firestore.rules`, add subcollection rules for movements:
       ```firestore
       // Movement logs subcollection
       match /users/{userId}/movements/{movementId} {
         allow read: if isOwner(userId);
         allow create: if isOwner(userId);
         allow update, delete: if false; // Immutable audit log
       }
       ```
  </action>
  <acceptance_criteria>
    - `src/types/inventory.ts` exports `StockMovement` with required audit attributes.
    - `firestore.rules` allows owner read/create on `/users/{userId}/movements/{movementId}` and rejects update/delete.
  </acceptance_criteria>

    <fails_when>non-zero exit code or missing audit security rules</fails_when>
  </verify>

  <action>
    1. In `src/hooks/use-inventory.ts`:
       - Subscribe to movements collection: `collection(firestore, 'users', user.uid, 'movements')`, ordered by `timestamp` desc with a limit of 100 entries.
       - Expose `movements: StockMovement[]` and `loadingMovements: boolean` from the hook.
       - Enhance `addItem`: After creating item doc, write a movement doc with type `'creation'`, `delta: item.quantity`, `previousQuantity: 0`, `newQuantity: item.quantity`, `timestamp: Date.now()`.
       - Enhance `updateItem`: Compute `delta = updatedItem.quantity - previousItem.quantity`. If `delta !== 0`, write a movement doc with type `delta > 0 ? 'restock' : 'reduction'`, recording previous and new quantities.
       - Enhance `deleteItem`: Before/after deleting item, write a movement doc with type `'deletion'`, `delta: -item.quantity`, `previousQuantity: item.quantity`, `newQuantity: 0`.
  </action>

    - `useInventory` exports `movements` array and `loadingMovements` status.
    - `addItem`, `updateItem`, and `deleteItem` write corresponding audit logs to Firestore.
    - Zero regression in existing inventory CRUD actions.
  </acceptance_criteria>
