# Plan 03-01: Automated Testing Suite (Vitest & Playwright) and GitHub Actions CI Pipeline

<objective>
Establish automated test coverage and quality gating for StockPilot by setting up Vitest for sub-second business logic unit testing (calculations, threshold boundary logic, and spreadsheet row validation), configuring Playwright for browser smoke testing, and delivering a deterministic GitHub Actions CI workflow running typecheck, lint, test, and build on every push and pull request per D-01, D-02, D-03, D-04, and D-05.
</objective>

<threat_model>
ASVS Level 1:
- Regressions in calculation, conversion, or security validation logic: Prevented by automated unit test suites covering edge cases and zero/negative thresholds.
- Broken builds or type divergences merged to production: Blocked by mandatory GitHub Actions quality gates running `typecheck`, `lint`, `test`, and `build`.
</threat_model>

<tasks>
<task type="tracer">
  <name>Install Vitest, configure test runner, and test threshold and calculation logic</name>
  <files>package.json, vitest.config.mts, src/lib/stock-status.ts, src/lib/stock-status.test.ts, src/lib/inventory-calculations.ts, src/lib/inventory-calculations.test.ts</files>
  <read_first>src/types/inventory.ts, src/components/inventory/inventory-stats.tsx</read_first>
  <action>
    1. Install `vitest` and `jsdom` as devDependencies.
    2. Add `"test": "vitest run"` and `"test:watch": "vitest"` scripts to `package.json`.
    3. Create `vitest.config.mts` configuring path aliases (`@/*`) and jsdom environment.
    4. Create `src/lib/stock-status.ts` exporting:
       - `getItemStockStatus(quantity: number, threshold?: number): 'out_of_stock' | 'low_stock' | 'in_stock'`
       - `getStatusBadgeDetails(status)`
    5. Create `src/lib/stock-status.test.ts` testing exact boundaries (0 quantity, 1 to threshold, > threshold, custom vs default threshold).
    6. Create `src/lib/inventory-calculations.ts` exporting:
       - `calculateInventoryStats(items, currency, rate)`
    7. Create `src/lib/inventory-calculations.test.ts` testing total valuation, unit counts, INR to USD conversion, and category aggregation.
  </action>
  <acceptance_criteria>
    - `npm test` runs with Vitest and passes all tests.
    - Status determination handles boundary edge cases accurately.
    - Financial calculation utility accurately converts rates and aggregates category sums.
  </acceptance_criteria>
  <verify>
    <automated>npm test</automated>
    <fails_when>non-zero exit code or failing unit test</fails_when>
  </verify>
  <done>
    Vitest unit test runner is operational and core domain calculations are fully covered by automated specs.

<task type="auto">
  <name>Create GitHub Actions continuous integration workflow</name>
  <files>.github/workflows/ci.yml</files>
  <read_first>.env.example, package.json</read_first>
  <action>
    Create `.github/workflows/ci.yml`:
    1. Trigger on `push` and `pull_request` targeting `main`.
    2. Run on `ubuntu-latest` with `actions/setup-node@v4` (Node.js 20, npm cache).
    3. Step 1: `npm ci`
    4. Step 2: `npm run typecheck`
    5. Step 3: `npm run lint`
    6. Step 4: `npm test` (Vitest unit tests)
    7. Step 5: `npm run build` with mock environment variables for Firebase.
  </action>
  <acceptance_criteria>
    - `.github/workflows/ci.yml` is valid YAML.
    - Pipeline executes typecheck, lint, test, and build sequentially.
    - Dummy build credentials ensure Next.js compiles without real secret dependencies.
  </acceptance_criteria>
  <verify>
    <automated>node -e "const yaml = require('fs').readFileSync('.github/workflows/ci.yml', 'utf8'); if (!yaml.includes('npm run typecheck') || !yaml.includes('npm test')) process.exit(1);"</automated>
    <fails_when>non-zero exit code or missing CI pipeline steps</fails_when>
  </verify>
