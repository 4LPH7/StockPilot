# Plan 03-02: Firebase Emulator Sandboxing, Storeroom Mobile Accessibility, and Portfolio README Showcase

<objective>
Elevate developer experience and portfolio presentation by establishing local Firebase Emulator sandboxing for offline testing, optimizing mobile storeroom accessibility (min 44px tap targets, explicit ARIA tags), and overhauling the README with live CI status badges, test documentation, emulator guide, and architectural diagrams per D-06, D-07, D-08, D-09, D-10, and D-11.
</objective>

<threat_model>
ASVS Level 1:
- Development data leakage to production Firebase projects: Mitigated by local Firebase Emulator sandbox isolating test mutations to localhost memory.
- Accessibility barriers on warehouse touch devices: Mitigated by WCAG 2.1 AA tap target sizing and screen-reader accessible ARIA labels.
</threat_model>

<tasks>
<task type="tracer">
  <name>Configure local Firebase Emulators for offline development</name>
  <files>firebase.json, src/firebase/config.ts, package.json</files>
  <read_first>src/firebase/config.ts, package.json</read_first>
  <action>
    1. Create `firebase.json` with emulator ports:
       - Firestore: 8080 (rules: "firestore.rules")
       - Auth: 9099
       - Emulator UI: 4000
    2. Update `src/firebase/config.ts`:
       - Conditionally connect to local emulators using `connectFirestoreEmulator` and `connectAuthEmulator` when `process.env.NEXT_PUBLIC_USE_FIREBASE_EMULATOR === "true"`.
    3. Add scripts to `package.json`:
       - `"emulators": "firebase emulators:start"`
       - `"dev:emulator": "NEXT_PUBLIC_USE_FIREBASE_EMULATOR=true next dev"`
  </action>
  <acceptance_criteria>
    - `firebase.json` configures Auth (9099) and Firestore (8080).
    - `src/firebase/config.ts` connects to localhost emulators when env flag is set.
    - `npm run typecheck` passes without errors.
  </acceptance_criteria>
  <verify>
    <automated>node -e "const f = JSON.parse(require('fs').readFileSync('firebase.json', 'utf8')); if (!f.emulators.firestore.port || !f.emulators.auth.port) process.exit(1);"</automated>
    <fails_when>non-zero exit code or missing emulator configuration</fails_when>
  </verify>
  <done>
    Local developers can run and test StockPilot completely offline without cloud dependencies.
  </done>
</task>
