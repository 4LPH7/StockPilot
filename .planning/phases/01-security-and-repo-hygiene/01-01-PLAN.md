# Plan 01-01: Security Rules, Per-User Data Isolation, and Authentication

<objective>
Harden the application security posture by externalizing Firebase credentials to environment variables, enforcing strict owner-only access and schema validation in Firestore rules under `/users/{uid}/items/{itemId}`, enabling Google and Email authentication, and updating data hooks and UI to reflect user session state per D-01, D-02, D-03, D-04, D-05, and D-06.
</objective>

<threat_model>
ASVS Level 1:
- Exposure of production secrets in source code: Mitigated by extracting keys to .env and gitignoring them (D-04, D-05, D-06).
- Insecure direct object reference (IDOR) & cross-tenant data corruption: Mitigated by partitioning documents under /users/{uid}/items and enforcing request.auth.uid == uid (D-01).
- Malicious/invalid payload injection: Mitigated by strict field and type validation rules in firestore.rules (D-02).
</threat_model>

<task type="auto">
  <name>Implement hardened Firestore security rules with per-user isolation and schema validation</name>
  <files>firestore.rules</files>
  <read_first>firestore.rules, src/types/inventory.ts</read_first>
  <action>
    Replace the open write rules in firestore.rules with strict per-user subcollection rules at /users/{userId}/items/{itemId}. Add helper functions isAuthenticated() and isOwner(userId) requiring request.auth.uid == userId. Add isValidItem(data) helper enforcing: name is string between 1 and 100 characters; description is optional string up to 500 characters; category is string between 1 and 50 characters; quantity is integer >= 0; price is number >= 0. Disallow unauthenticated reading or writing per D-01 and D-02.
  </action>
  <acceptance_criteria>
    - firestore.rules matches /users/{userId}/items/{itemId}.
    - Read/write access strictly requires request.auth.uid == userId.
    - isValidItem validates name, category, non-negative quantity, and non-negative price.
  </acceptance_criteria>
  <verify>
    <automated>node -e "const fs = require('fs'); const rules = fs.readFileSync('firestore.rules', 'utf8'); if (!rules.includes('/users/{userId}/items/{itemId}') || !rules.includes('isValidItem')) process.exit(1);"</automated>
    <fails_when>non-zero exit code or rules missing required helper or path</fails_when>
  </verify>
  <done>
